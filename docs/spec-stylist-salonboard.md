# 実装依頼（Claude Code）：スタイリスト別の実績をサロンボードに統一

## 確定方針（2026-06-24）
スタッフ単位の「実績系」数値を**サロンボード実績に統一**する。サロンボードに無いスタッフは月末報告書へフォールバック。

| 指標 | ソース |
| --- | --- |
| 売上（技術／店販／総） | サロンボード |
| 客数（＝稼働率の実客数もこれ） | サロンボード |
| 新規客数・再来客数 | サロンボード |
| 指名数 | サロンボード |
| 次回予約（率） | 月末報告書（サロンボードに無い） |
| 雇用形態 | スタッフマスタ（月末報告書） |
| NPS | NPSシート（従来どおり） |

名寄せ（canonical）＝**サロンボード（ホットペッパー）の担当名を正**とし、月末報告書・NPS・ファンくるの表記ゆれは `stylist_aliases`（管理ページの対応表）でサロンボード名へ寄せる。ファンくるの特定は既存の `useFankuruData` ＋ `stylist_aliases`（DB優先）ロジックを活用。

## 既存資産
- スクレイパー `../salonboard-scraper/aggregate_stylist.js` → `output/stylist_summary.csv`（店舗/スタイリスト/年月/売上/客数/客単価/指名数）。
- 売上明細CSVには1会計ごとに「新規/再来」フラグ（明細列20）と担当スタイリスト（列12）があるため、**スタイリスト別の新規・再来も集計可能**（現状は未集計）。
- `salonboard-scraper/GoogleSheet連携_手順.md` のApps Scriptがスプレッドシートへ取り込み済み。

## 作業
1. **スクレイパー拡張**：`aggregate_stylist.js` に per-stylist の新規・再来集計を追加（明細列20を使用）。`stylist_summary.csv` の列に `新規,再来` を追加。
2. **シート供給**：GoogleSheet連携のApps Scriptに、全店まとめの1タブ `stylist_flat` を追加出力（行＝`店舗,スタイリスト,年月,売上,客数,客単価,指名,新規,再来`）。リンク閲覧可にし gviz CSV で取得可能にする。
3. **クライアント新フック**：`client/src/hooks/useSalonBoardStylistData.ts` を `useSalonBoardData.ts` に倣って作成。キー＝店舗×スタイリスト×年月。売上・客数・新規・再来・指名を返す。名寄せは `stylist_aliases`（DB）でサロンボード名へ。
4. **配線**：
   - `StaffList.tsx` / `StaffDetail.tsx` の 売上・客数・新規・再来 を「サロンボード優先・無ければ月末報告書フォールバック」に変更。`dataSource: "salonboard"|"report"` を持たせる（Home/StoreDetailと同じ流儀）。
   - 稼働率（`utilizationRate`）の実客数はサロンボード客数を使用。
   - 次回予約率は `useMonthlyReport`、雇用形態はマスタのまま（変更禁止）。
5. **テスト**：新フックのパース／名寄せ、稼働率の客数切替のユニットテストを追加。全テスト緑を確認。
6. **コミット＆プッシュ**（GitHub認証は林さんが実施）。

## 完了条件
スタッフ一覧／詳細の売上・客数・新規・再来がサロンボード値で表示され、無いスタッフは月末報告書にフォールバック。稼働率の分子もサロンボード客数。次回予約・雇用形態・NPSは従来どおり。全テスト緑。
