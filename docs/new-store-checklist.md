# 新店舗追加チェックリスト

monet ダッシュボードに新店舗を反映するための確認事項をまとめたドキュメントです。定期タスク（毎月5日）で自動処理される項目と、手動対応が必要な項目を明確に区別しています。

---

## 自動で反映される項目

以下の項目は、月末報告書スプレッドシートに新店舗のデータが入力されていれば、**毎月5日の定期タスクで自動的に処理**されます。

| 項目 | 処理内容 | 条件 |
|------|---------|------|
| 店舗マスタ登録 | DBに新店舗を自動INSERT | 月末報告書に未知の店舗名が存在する |
| エリア判定 | 店舗名の地名キーワードから自動分類 | 「広島」「福岡」「大阪」等が含まれる場合 |
| ダッシュボード店舗一覧 | DB参照のため追加操作不要 | 上記の登録が完了していれば即反映 |
| サロンボードシート名マッチング | シート名のキーワードから自動紐づけ | シート名に店舗名の一部が含まれる場合 |
| オーナー通知 | 新店舗検出結果をManusの通知で送信 | 常に実行 |

---

## 手動対応が必要な項目

以下の項目は自動化されていないため、新店舗オープン時に手動で対応する必要があります。

### 1. NPSスプレッドシートの店舗名パーサー

**対象ファイル:** `client/src/hooks/useNpsData.ts` — `parseStoreName` 関数

NPSアンケートの店舗名（例: `monet[モネ] 白髪染めと髪質改善のサロン 土橋院`）を短縮名（例: `広島土橋院`）に変換する処理です。新店舗の命名パターンが既存のルールに合致しない場合、パーサーに追加が必要です。

```typescript
// 追加例
if (fullName.includes("○○院")) return "広島○○院";
```

> **確認方法:** NPSスプレッドシートに新店舗のデータが入った後、ダッシュボードのNPSスコアが表示されるか確認する。表示されない場合はパーサーの修正が必要。

---

### 2. 月末報告書の店舗名正規化マッピング

**対象ファイル:** `client/src/hooks/useMonthlyReport.ts` — `STORE_NAME_MAP`

月末報告書スプレッドシートでの店舗名表記（例: `広島土橋院`）をダッシュボード上の正規名に変換するマッピングです。新店舗の表記がそのまま使える場合は追加不要ですが、表記揺れがある場合は追加が必要です。

```typescript
// 追加例
"広島土橋院": "広島土橋院",
"土橋院": "広島土橋院",
```

> **確認方法:** 月末報告書に新店舗のデータが入った後、ダッシュボードの売上・客数が表示されるか確認する。

---

### 3. サロンボードのシート名マッピング（自動マッチ失敗時のみ）

**対象ファイル:** `client/src/hooks/useSalonBoardData.ts` — `SHEET_STORE_MAP`

定期タスクがシート名を自動マッチングしますが、シート名から店舗名を推定できない場合（例: `monet広島_月別` が楽々園院を指すケース）は手動で設定が必要です。

```typescript
// 追加例
{ sheetName: "monet土橋_月別", storeName: "広島土橋院" },
```

> **確認方法:** 定期タスクの通知に「マッチできなかったシート」が報告された場合に対応する。

---

### 4. ファンくるの店舗名正規化マッピング

**対象ファイル:** `client/src/hooks/useFankuruData.ts` — `STORE_NAME_NORMALIZE`

ファンくるスプレッドシートでの店舗名表記をダッシュボード上の正規名に変換するマッピングです。

```typescript
// 追加例
"広島土橋院": "広島土橋院",
```

> **確認方法:** ファンくるのPDFデータが新店舗のスタッフに紐づいて表示されるか確認する。

---

### 5. NEWバッジの既知店舗リスト

**対象ファイル:** `client/src/lib/newBadge.ts` — `KNOWN_STORES`

新店舗に「NEW」バッジを表示するための既知店舗セットです。新店舗をここに追加しないと、永久にNEWバッジが表示され続けます（通常はオープンから3ヶ月後に追加）。

```typescript
// 追加例（オープン3ヶ月後に追加）
"広島土橋院",
```

> **確認方法:** 3ヶ月経過後もNEWバッジが表示されている場合に追加する。

---

### 6. エリア判定が「未分類」になった場合

定期タスクのエリア自動判定は、店舗名に含まれる地名キーワードに基づきます。以下のキーワードに該当しない場合は「未分類エリア」として登録されます。

| キーワード | 判定エリア |
|-----------|-----------|
| 堀江、福島、高槻、大阪 | 大阪エリア |
| 姪浜、福岡 | 福岡エリア |
| 楽々園、広島、土橋 | 広島エリア |

上記に該当しない場合は、DBの `stores` テーブルの `area` カラムを手動で更新してください。

---

## 対応タイミングの目安

| タイミング | 対応内容 |
|-----------|---------|
| 新店舗オープン前 | 特になし（データが入るまで待つ） |
| 月末報告書にデータが入った翌月5日 | 定期タスクが自動検出・登録。通知を確認 |
| 通知確認後 | 手動対応項目（上記1〜4）を確認し、必要に応じて修正 |
| オープン3ヶ月後 | NEWバッジの既知店舗リストに追加（項目5） |

---

## 将来の改善案

現在手動対応が必要な項目のうち、以下はDB化によって自動化可能です：

- **SHEET_STORE_MAP** → DBの `salonBoardSheetName` を参照する形に切り替え（定期タスクで自動更新済み）
- **STORE_NAME_MAP / STORE_NAME_NORMALIZE** → DBに `aliases` カラムを追加し、表記揺れを一元管理
- **parseStoreName** → 汎用パターンマッチ（`〇〇院` を抽出）で大半は対応可能。DB店舗名との照合で自動判定

これらを実装すれば、手動対応は「エリア判定の修正」と「NEWバッジの期限管理」のみに削減できます。
